从 backup 取回 `adapter/hydro/**` + `doc/Hydro/**` → 重新落地。

没用 `git merge -X theirs`：它只按 hunk 判冲突，会把「我加在非重叠位置的改动」也带进来

reset + 取回是确定性的，PR diff 也干净（= main + 一个新适配器 + 文档）。

## 二、逻辑冲突与取舍

### 1. infra 在非 2xx 时丢弃响应体 → ✅ 已修（新增 raw 变体）

**状态：✅ 已修（infra 新增 raw 变体）**

修法：`HttpClient` 增加一组 **raw 变体** —— `get_text_raw` / `post_text_raw` 返回
`(StatusCode, HeaderMap, String)`，**任意状态码都返回原始响应**，不做状态码 → `AppError`
映射。重试策略保持：5xx 仍退避重试（GET 幂等），**耗尽后返回响应而不是报错**；4xx 不重试。
策略判定仍在纯函数 `classify_status(status, attempt, allow_error)` 里，单测覆盖了两组语义
（默认组「耗尽即报错」与 raw 组「任意状态码原样返回」）。

Hydro 侧随之**两条通道合一**：GET 与 POST 都走 infra raw 变体，适配器不再直连
`reqwest`（`http.client()` 只留给 HOJ 的登录路径）。代价是 401 不再由 infra 自动映射为
`Auth` —— raw 变体的调用方必须自己映射，Hydro 用 `http_status_error` 承担（判据与 infra
的 `status_error` 逐条对齐，避免会话守卫失效）。

**为什么不用「让非 raw 变体也返回响应体」来修**：那会改变 HOJ 的既有语义（它依赖
「非 2xx 即 `Err`，401 即 `Auth`」），把两种用法混在一个返回值里只会让每个调用点都要
判断「这次到底是错误还是正常返回」。分两组变体，选择权在调用点，语义各自单纯。

<details>
<summary>原始记录（保留以说明背景）</summary>

**现象**：`HttpClient::get_text_with_headers` / `post_text_with_headers` 在非 2xx 时
直接返回 `Err(status_error(url, status))` —— **响应体被丢掉**。而 Hydro 的用户可见错误
**全在响应体的包络里**：`{"error":{"name":"LoginError","params":["alice"],"code":403}}`
（没有 message，`name` 是唯一线索）。

**影响**：
- 登录失败：拿不到 `LoginError` → 只能给用户看「HTTP 403 Forbidden: https://…/login」，
  而不是「用户名或密码错误」；
- 限流/权限：拿不到 `OpcountExceededError` / `PermissionError`，无法区分「被限流」与「密码错」；
- **会话失效检测**：Hydro 匿名访问在 JSON 模式下通常是 **HTTP 200 + `{"url":"/login?…"}`**，
  这条路径不经过状态码分支，仍可靠；但若某部署匿名时直接返回 403 `PrivilegeError`，
  就会被归成 `Network`（**不触发登出**）。

**当时的折中**：GET 走 infra（要 5xx 退避重试与统一 401→`Auth`）、POST 走原始 `reqwest`
（POST 本就不重试，且要读错误包络与 `Set-Cookie`）。残余风险是 GET 的 4xx 包络拿不到。

</details>

### 2. 前端只能切换与编辑实例，不能新增实例 → ✅ 已修（枚举选择器 + 按需注册）

**状态：✅ 已修（枚举选择器 + 按需注册，刻意不做实例 CRUD）**

按「固定枚举」方案解决，三步：
1. **前端枚举**：新增 `src/utils/oj.ts` 作为 OJ 类型域的唯一权威（`OJ_TYPES = ['HOJ', 'Hydro']`），
   下拉候选 = 枚举 ∪ 配置里出现的其它 id（手改配置的私有部署仍显示，不丢信息）；
   未配置的类型标注「（未配置）」；
2. **保存即建实例**：选中未配置的类型 → 引导填地址 → 「保存」把实例 upsert 进
   `oj.instances`（`enabled: true`），并**自动完成切换**（用户在选下拉时已表达切换意图）；
3. **后端按需注册**：新增 `AppContext::ensure_oj_registered(id)`（幂等），`switch_oj` 在
   校验前调用 —— 否则新实例要重启客户端才生效，UI 上表现为「切换失败：OJ 未注册」。

判定条件与启动注册**同源**（只认「配置里已启用且 id 匹配」的实例，共用纯函数
`enabled_instance`）：不能让 `switch_oj` 变成绕过配置凭空激活 OJ 的后门。

**为什么不做「实例增删管理」**：本项目面向校内赛的少数几个已知 OJ，固定枚举足够且更简单；
id 会拼进会话文件名（`sessions/{id}.json`），让用户在 UI 里自由拼 id 只会增加出错面。
枚举外的自定义部署仍可通过手改 `config.json` 使用（UI 会如实显示）。

**遗留**：`OJ_TYPES` 与后端 `adapter::factories()` 需要人工同步（新增 OJ 时两处各加一项）。
若将来枚举变长，可考虑由后端暴露「已知 OJ 类型」清单给前端（那时再加命令与 bridge）。

<summary>原始记录（保留以说明背景）</summary>
核心方法 / `adapter::hoj::types::is_terminal_status` / 前端 `utils/submission.isTerminalStatus`。
**Hydro 是第 4 处**：`adapter::hydro::types::is_terminal_status`（Hydro 原始码 0/20/21/22 之外皆终态）。

**为什么必须一致**：`service/submission/mod.rs:249` 用 `detail.status.is_terminal()` 决定

「评测中」的结果缓存下来，界面永远停在评测中。

**已核对（实现是对的）**：Hydro `{0,20,21,22}` → `{Pending, Running, Compiling, Pending}`
（全非终态）；`22 FETCHED` 特意折成 `Pending` 而非 `Unknown`，正是为了满足这条 ——
折成 `Unknown` 会让轮询在评测开始前就停住、并把在途结果写进缓存。

</details>

### 4. `OjInstance.options` 传不进适配器 → ⏸ 待决断

**状态：⏸ 未做（属 D4 的决策范围）**

**现象**：`AdapterFactory::build(&self, deps, base_url)` 只把地址交给适配器；
`OjInstance.options`（弱类型私有旋钮）没有传递通道。

**影响**：缺口 D4（Hydro 多域部署需要 `/d/:domainId` 前缀）**有地方配了、但送不进去**。
当前适配器按系统域拼路径，自定义域部署会 404。

**可选补丁**（择一）：
- `build(&self, deps, instance: &OjInstance)` —— 适配器自己挑 options（推荐，形状也贴近插件 manifest）；
- 或 `build(&self, deps, base_url, options: &Map<String, Value>)`。

**待你确认**：目标部署是否用自定义域。不用的话本条可降为备案。

### 5. `ContestProblem.cid` 仍是 `i64` → ✅ 已修（改 `String`）

**状态：✅ 已修（`cid` 改为 `String`）**

改动面（跨端契约，一次性改完）：`core/entity/contest.rs`（`cid: String`）、
`adapter/hoj`（`p.cid.to_string()`）、`adapter/hydro`（如实携带 24 位 hex ObjectId，
`map_contest_problems` 增加 `contest_id` 形参）、前端 `src/types/contest.ts`（`cid: string`）、
以及 2 处测试夹具。语义与 `OjConfig::contest_ref` 对齐：**比赛是对服务端资源的不透明引用**，
不该假设它是数字。

### 6. `HttpClient` 的 Cookie jar 仍全局共享 → ⏸ 待决断（当前无实害）

**状态：⏸ 未做（当前无实害）**

`cookie_store(true)` 的 jar 在进程内共享。Hydro 登录后 `sid` 会留在里面。
新架构让**适配器实例按 OJ 实例构造**（内存会话天然隔离），但 **jar 没有隔离** ——
同一主机上的多套部署仍可能串扰。当前只有「一个 active OJ」，无实害。

## 三、已核对一致的地方（不用操心）

| 项 | 结论 |
|---|---|
| 会话文件名 | `HydroAdapter::ID = "Hydro"` → `sessions/Hydro.json`，与 `OjId` 契约一致；Hydro 无历史会话，无需迁移 |
| 终态判据 | Hydro 原始码 → 核心变体的映射与 `is_terminal()` 一致（见 2.3） |
| OJ 切换与缓存 | `OJSwitched` 会清 contest/problem/submission 的缓存；适配器实例按实例构造，我的 `pid_cache`（比赛题目顺序）不跨 OJ，无需额外订阅 |
| 缓存原语 | 我原来手写的 `RwLock<HashMap<…, Instant>>` 换成了他们的 `infra::cache::TtlCache`（TTL + 容量淘汰由原语负责） |
| 配置迁移 | `user.lastOjType` → `oj.active`、`hojUrl` → `instances`、`contestId` → `contestRef` 由他们的 `normalize_legacy_values` 处理，我不需要再管 |

## 四、结论（2026-09-19 晚更新）

**本轮改动**（用户批准后实施，4 项）：

| 项 | 改动 | 影响面 |
|---|---|---|
| ① infra raw 变体 | `HttpClient` 新增 `get_text_raw` / `post_text_raw`（任意状态码都返回 status+headers+body），`classify_status` 增加 `allow_error` 参数 | `infra/http.rs` + 测试；Hydro 两条通道合一，不再直连 reqwest |
| ② OJ 枚举选择器 | 新增 `src/utils/oj.ts`（枚举 + 候选组装）；`SettingsView` 支持选中未配置类型 → 保存建实例 → 自动切换；后端 `AppContext::ensure_oj_registered` 让新实例**免重启**生效 | 前端 3 文件 + `core/context.rs` + `commands/oj_cmd.rs` |
| ③ `is_terminal` 判据清单 | 三处 → 四处（补 Hydro 与 22 FETCHED 的理由） | `core/entity/submission.rs` 注释 |
| ⑤ `cid` 改字符串 | `ContestProblem.cid: String`，HOJ 传数字串、Hydro 传 ObjectId | entity + 2 个 adapter + 前端类型 + 2 处测试夹具 |

**仍待你决断**：④ `OjInstance.options` 传不进适配器（要不要做 Hydro 的 `/d/:domainId`）、
⑥ Cookie jar 全局共享（当前无实害）。

前端 `vitest run` 377 passed、`vue-tsc --noEmit` 通过。
