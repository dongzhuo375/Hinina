**做法**：`git branch backup/hydro-adapter-v1` 留底 → `git reset --hard main` →
从 backup 取回 `adapter/hydro/**` + `doc/Hydro/**` → 重新落地。

没用 `git merge -X theirs`：它只按 hunk 判冲突，会把「我加在非重叠位置的改动」也带进来
（例如 `mod_tests.rs` 里调用已删除的 `parse_oj_type` 的用例），得靠编译器一个个发现；
reset + 取回是确定性的，PR diff 也干净（= main + 一个新适配器 + 文档）。

**作废清单**（他们的实现都更彻底，无需保留）：

- 会话路径的 `format!("{:?}", oj_type)` → `OjId::session_file()` 取代（这条是我提的隐患，他们修了）

## 二、逻辑冲突与取舍

### 1. infra 在非 2xx 时丢弃响应体（D17 修好了，但换来一条更窄的缺口）

**现象**：`HttpClient::get_text_with_headers` / `post_text_with_headers` 在非 2xx 时
直接返回 `Err(status_error(url, status))` —— **响应体被丢掉**。而 Hydro 的用户可见错误
**全在响应体的包络里**：`{"error":{"name":"LoginError","params":["alice"],"code":403}}`
（没有 message，`name` 是唯一线索）。

**影响**：
- 登录失败：拿不到 `LoginError` → 只能给用户看「HTTP 403 Forbidden: https://…/login」，
  而不是「用户名或密码错误」；
- 限流/权限：拿不到 `OpcountExceededError` / `PermissionError`，无法区分「被限流」与「密码错」；
- **会话失效检测**：Hydro 匿名访问在 JSON 模式下通常是 **HTTP 200 + `{"url":"/login?…"}`**，
  这条路径不经过状态码分支，仍可靠；但若某部署匿名时直接返回 403 `PrivilegeError`，
  就会被归成 `Network`（**不触发登出**）。

**我的分工**（`adapter/hydro/mod.rs`）：
- **GET 走 infra**：幂等方法，值得要回 5xx 退避重试与统一的 401→`Auth` 映射；
- **POST 走原始 `reqwest`**：POST 本来就不重试（infra 也不重试 POST），所以走原始通道
  **不损失重试**；而登录/提交的文案质量与「登录要读 `Set-Cookie`」都依赖原始响应。

**残余风险**：GET 的 4xx 包络仍拿不到（上面第三条）。

**建议补丁**（infra，新增变体、不动既有方法）：
```rust
/// 任意状态码都返回 status + headers + body（供需要读错误包络的适配器使用）
pub async fn get_text_raw(
    &self, url: &str, headers: &HeaderMap,
) -> AppResult<(reqwest::StatusCode, HeaderMap, String)>;
```
有了它，Hydro 的 GET 也能读包络，两条通道可以合并成一条（都走 infra，都保留重试）。
**在补丁落地前，现分工是收益最大的折中。**

### 2. 前端只能切换与编辑实例，不能新增实例

**现象**：`SettingsView` 的 OJ 下拉候选来自 `oj.instances`，可以切换（`switch_oj`）与
改当前实例的地址；但**没有新增/删除实例的入口**，`default_oj_instances()` 也只给 HOJ 一条。

**影响**：接入新 OJ 的最后一公里仍要手改 `config.json`：
```json
{ "oj": { "active": "Hydro",
          "instances": [ { "id": "HOJ", "baseUrl": "https://hoj.…", "enabled": true },
                         { "id": "Hydro", "baseUrl": "https://hydro.ac", "enabled": true, "options": {} } ] } }
```
否则下拉里根本没有 Hydro 可切。这属于缺口报告 D3 的**残差**（D3 的「无入口」已解决，
「无法自助新增」未解决）。

**建议**：设置页 OJ 分组加「添加实例」（id 从已注册工厂里选、地址、启用开关）。
**本轮未做**（前端不在本次范围）。

### 3. `JudgementStatus::is_terminal()` 的一致性清单少了 Hydro

**现象**：`core/entity/submission.rs:37` 的注释写明「三处判据必须保持一致」：
核心方法 / `adapter::hoj::types::is_terminal_status` / 前端 `utils/submission.isTerminalStatus`。
**Hydro 是第 4 处**：`adapter::hydro::types::is_terminal_status`（Hydro 原始码 0/20/21/22 之外皆终态）。

**为什么必须一致**：`service/submission/mod.rs:249` 用 `detail.status.is_terminal()` 决定
「终态提交详情/测试点才可缓存」。若 Hydro 的**非终态**码映射到核心**终态**变体，就会把
「评测中」的结果缓存下来，界面永远停在评测中。

**已核对（本次实现是对的）**：Hydro `{0,20,21,22}` → `{Pending, Running, Compiling, Pending}`
（全非终态）；`22 FETCHED` 特意折成 `Pending` 而非 `Unknown`，正是为了满足这条 ——
折成 `Unknown` 会让轮询在评测开始前就停住、并把在途结果写进缓存。

**建议**：把那句注释的三处清单改成四处并补上 Hydro（文档级，1 行）。

### 4. `OjInstance.options` 传不进适配器

**现象**：`AdapterFactory::build(&self, deps, base_url)` 只把地址交给适配器；
`OjInstance.options`（弱类型私有旋钮）没有传递通道。

**影响**：缺口 D4（Hydro 多域部署需要 `/d/:domainId` 前缀）**有地方配了、但送不进去**。
当前适配器按系统域拼路径，自定义域部署会 404。

**可选补丁**（择一）：
- `build(&self, deps, instance: &OjInstance)` —— 适配器自己挑 options（推荐，形状也贴近插件 manifest）；
- 或 `build(&self, deps, base_url, options: &Map<String, Value>)`。

**本轮未做**（属 D4 的决策范围，等你定）。

### 5. `ContestProblem.cid` 仍是 `i64`（D1 未解决）

Hydro 的比赛 ID 是 24 位 hex ObjectId，装不进 `i64` → `list_contest_problems` 只能填 `0`。
当前前端不消费该字段，无功能故障；要修就得改 entity + 前端类型（跨端契约）。

### 6. `HttpClient` 的 Cookie jar 仍全局共享（D14）

`cookie_store(true)` 的 jar 在进程内共享。Hydro 登录后 `sid` 会留在里面。
新架构让**适配器实例按 OJ 实例构造**（内存会话天然隔离），但 **jar 没有隔离** ——
同一主机上的多套部署仍可能串扰。当前只有「一个 active OJ」，无实害。

## 三、已核对一致的地方（不用操心）

| 项 | 结论 |
|---|---|
| 会话文件名 | `HydroAdapter::ID = "Hydro"` → `sessions/Hydro.json`，与 `OjId` 契约一致；Hydro 无历史会话，无需迁移 |
| 终态判据 | Hydro 原始码 → 核心变体的映射与 `is_terminal()` 一致（见 2.3） |
| OJ 切换与缓存 | `OJSwitched` 会清 contest/problem/submission 的缓存；适配器实例按实例构造，我的 `pid_cache`（比赛题目顺序）不跨 OJ，无需额外订阅 |
| 缓存原语 | 我原来手写的 `RwLock<HashMap<…, Instant>>` 换成了他们的 `infra::cache::TtlCache`（TTL + 容量淘汰由原语负责） |
| 配置迁移 | `user.lastOjType` → `oj.active`、`hojUrl` → `instances`、`contestId` → `contestRef` 由他们的 `normalize_legacy_values` 处理，我不需要再管 |

## 四、本轮结论

- **没有需要改他们代码的地方**（除 `adapter/mod.rs` 2 行接线）；
- 待你决断的两条建议补丁：**infra 提供「非 2xx 也带 body」的变体**（收益明确、风险极低）、
  **设置页支持新增 OJ 实例**（决定 Hydro 能否被选手自助启用）；
- 文档级建议一条：`is_terminal()` 的「三处判据」补成四处（含 Hydro）。
