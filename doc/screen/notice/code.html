程序设计竞赛学术诚信与现场纪律违规判定细则（2024版）

为保证本届程序设计竞赛的公平、公正与严肃性，竞赛组委会制定本细则。所有参赛队伍及选手自登入 Hinina OJ 客户端起，即视为知晓并完全承诺遵守下列行为规范：

一、代码原创性与查重认定机制

1. 比赛期间提交的所有源代码，必须由当前参赛队伍的正式注册成员在现场独立编写。严禁在比赛中使用任何形式的代码生成工具、预先录制的外部代码片段（非队伍携带的标准纸质资料）或未经许可的第三方库。
2. 比赛结束后，系统将自动进入代码静态查重程序，结合语法树（AST）分析与隐式特征比对。凡相似度超过 85% 且无合理算法特异性的队伍提交，经裁判组复核后将取消比赛成绩并通报所属高校。

二、网络与通信设备使用规范

1. 严禁选手在竞赛用机上通过任何手段访问局域网以外的公网服务，包括但不限于即时通讯工具、私有代码仓库、在线编译平台及技术论坛。
2. 参赛期间机位周围严禁开启移动热点、智能手表、带通信功能的可穿戴设备。一经发现违规携带已开启无线通信模块的电子设备，将直接记为严重违纪并终止其参赛资格。

三、现场质疑与违纪申诉程序

若队伍对现场评测结果或题目题意存在严重异议，应通过客户端内置 Clarification（答疑通道）提出，或在规定时间内举手向现场裁判长提交书面申诉。对于扰乱考场纪律、恶意攻击评测系统或破坏机房网络拓扑的队伍，组委会保留追加纪律处分的权利。

程序设计竞赛参赛守则、网络环境合规与突发情况应急预案

为保障 2024 年度校赛模拟赛及后续 ICPC/CCPC 选拔赛事的公正、严肃与平稳运行，组委会与技术仲裁委员会特此发布本规范细则。请全体参赛选手知悉并严格遵守：

一、行为规范与学术诚信

比赛期间严格禁止任何形式的代码抄袭、多队协同交流或外部作弊行为。所有提交至评测机系统的源代码均会在赛后及赛中实时运行 AST（抽象语法树）同源相似度分析。任何雷同代码经仲裁委员会复核确认后，将直接取消涉事队伍参赛成绩，并依规通报院校处理。

二、本地文件保存与自动备份注意

客户端底部状态栏已启用 Auto-Save Active 自动草稿缓存功能，但选手本地编写的代码文件仍须规范存放在桌面指定的 workspace/team_code 工作目录中。严禁随意修改评测沙箱运行环境路径或覆盖系统配置文件，以防突发断电或重启导致未提交的未保存代码丢失。

三、网络限制与外联违规定义

机房网络处于白名单隔离模式，仅允许访问 Hinina OJ 内部评测通信域名（judge.hinina.internal）及官方预置的离线语言文档（C++ cppreference、Java API docs 与 Python docs）。选手严禁尝试使用代理工具绕过白名单，禁止携带或接入未经报备的随身 WiFi、移动热点及私有存储设备，违者按严重违纪处理。

四、硬件或评测机故障应对动线

如遇本地机器死机、键盘鼠标故障、网络连接中断或评测长时间处于 Judgement Pending 超过合理时限（2 分钟以上），请勿自行强制切断电源或大声喧哗。请保持座位端正并立即举手示意现场技术志愿者，由现场技术主管裁判到场核实记录，并根据故障时长及影响范围启动补时或更换备用机动席位流程。

关于 C 题「计算混淆」数据范围与输出格式补充说明

经裁判组核实，原题面中子任务 2 的数据规模约束描述存在歧义。请参赛队伍注意以下补充与修正，评测机后台已同步更新数据校验脚本：

1. 对于 100% 的评测数据，保证序列长度 1 ≤ N ≤ 10^5（原描述误写作 10^3）。
2. 若存在多组最优逆序对变换路径，只需输出字典序最小的一组解。
3. 输出每行末尾允许包含多余空格，但最后一行必须以换行符 '\n' 结束。

B 题「新港之瓶」样例 2 解释修正说明

题目 B 中 Sample 2 的解释文本中第二步倒水操作容量计算中，“倒出 3L 残液”应修正为“倒出 2L 残液”。样例输入数据及期望输出标准答案保持不变，无需重新提交已通过的代码。

关于比赛最后 1 小时封榜规则与气球发放通知

各位参赛选手请注意以下赛中关键节点时间：

  • 封榜时间：比赛将于第四小时结束时（13:00:00）准时开启滚榜冻结，期间各队仍可正常提交，但榜单将显示 ? (Pending) 状态。
  • 气球发放：最后 1 小时内通过的题目将暂停发放对应颜色气球，闭幕式滚榜环节统一公布。
  • 如遇客户端故障或网络异常，请举手示意现场技术志愿者。
