### 1. P66 —— 移除 localStorage 用户缓存死代码

`login` / `checkSession` 把含 token 的完整 `User` JSON 写进 localStorage，`logout` 清除，
但唯一读取方 `getStoredUser` 只被测试引用 —— 「只写不读」的死代码，且是可被同源脚本读取的暴露面。

**改动**：删除 `STORED_USER_KEY` / `getStoredUser` / `clearStoredUser` 及三处写入；
`stores/session.ts` 的 OJ 切换重置不再调用 `clearStoredUser`（认证态本就置空）。

### 2. P67（第 1、2 条）—— 修正与实现不符的注释

- 头注「打开题目时自动创建/加载对应 Workspace」→ 实际 `open_problem` 只发布 `ProblemEvent::Opened`

**改动**：两处改为如实描述。

### 3. P4 —— 测试临时目录改为 RAII 守卫

**复现（改造前）**：跑一次全量测试后 `%TEMP%` 残留 **1708 个** `hinina-*` 目录。

**改动**：新增 `src-tauri/src/test_support.rs`（`cfg(test)`）：

- `TempDir`：构造时清同名残留，`Drop` 时递归删除；额外实现 `Deref<Target = Path>` /
  `AsRef<Path>` / `PartialEq<TempDir> for PathBuf`，让既有断言与路径用法零改写
- `Guarded<T>`：`Deref` 转发，把目录生命周期绑到既有被测对象上 —— 调用点不必手工
  接住守卫（漏接会静默退回「不清理」，这正是要避免的失效模式）

转换 13 个测试文件（infra / service×6 / core / adapter×2 / commands），删除各用例末尾的手工清理。
`TempDir` 额外实现 `Deref<Target = Path>` / `AsRef<Path>` / `PartialEq<TempDir> for PathBuf`，
使既有断言与路径用法（`&dir`、`dir.join(..)`、`assert_eq!(pathbuf, dir)`）无需逐处改写。

**验证（改造后）**：同一条命令跑完，残留 **0**。

### 4. P71 —— 榜单分页默认值的唯一取值点

三处硬编码 50，且前端恒显式传参 → 后端两处实际不生效，漂移**没有任何运行时症状**。

**改动**：前端 `DEFAULT_RANK_PAGE_SIZE` 明确为唯一取值点；后端两处保留为防御并注释指向它

（`rank.service` 此前**无任何单元测试**）。

### 5. P68 —— `sessionGuard` 移出 `stores/`

它是装配函数 + 模块级标志，没有 `defineStore`；而它又需要 `router` 与 `authStore` ——

**改动**：新建 `src/guards/` 承载「跨层装配」（与 `router/`、`utils/`、`types/` 同属不在

### 6. P70 —— 删除 `list_problems` 死链

整条链零调用方（题目列表实际走 `ContestProvider::list_contest_problems`）；即便被调用也是

**改动**：删除 trait 方法、HOJ/hydro 实现、command 与 `main.rs` 注册、前端三层与 store state，

### 7. P64 + P30 —— 时间解析上提共用实现

**复现（旧实现）**：对实测格式 `2026-09-21T16:00:00.000+0800`，旧实现按固定 19 字符取位，
得到与 `...T16:00:00Z` **相同**的值（差 28800 秒）—— 即偏移被静默忽略；非零填充的
`2024-1-1 8:00:00` 因长度不足 19 直接归 0。

同时发现 Hydro 侧的解析器虽能处理偏移，但对只有日期的串（`2026-01-01`）会 **panic**
（`rest` 为空串时 `[1..]` 越界，未覆盖边界）。

**改动**：上提为 `adapter/time.rs`（两个 Adapter 共用，避免「修好一个」不等于「修好全部」），
按字段切分而非固定取位；支持毫秒 / `Z` / `±HHMM` / `±HH:MM` / 空格分隔 / 非零填充 / 仅日期；
**非零偏移与解析失败均 `warn!`**（部署时区异常与格式变化的第一现场信号）；空串按「未设置」不告警；
日期要求「年-月-日」齐全（`2024` 这类残缺值仍归 0，不静默折算成 1 月 1 日）；修掉空串 panic。

**签名不变（仍返回 `i64`，0 = 未设置）**：改 `Option` 会牵动实体 / DTO / 前端，且
`getContestPhase` 依赖该值 —— 本轮只消除「静默」，把影响面控制在 adapter 层。

**新增 13 条解析用例**，含「带偏移 ≠ 显式 UTC 写法」的锁定。

### 8. P48 + P74-1 —— auto-save 按配置热生效

**复现（旧实现）**：`static STARTED: AtomicBool` 一次性懒启动 —— 设置页关掉 auto-save 后
再也打不开；间隔只读首次 `load_workspace` 的配置。

**改动**：

- `WorkspaceManager` 增加实例级 `auto_save_interval_secs`（`None` = 未运行），start/stop 同步维护
- 判据抽成纯函数 `auto_save_action(auto_save, interval, current)` → `Keep` / `Start` / `Stop`：
  间隔未变则 Keep（避免每次加载都重置计时器）、间隔变了才重启、关闭则 Stop、间隔 0 视为关闭
- `start_auto_save_if_needed` → 幂等的 `sync_auto_save_with_config(editor, wm)`，
  调用点：`load_workspace` + `update_config` / `reload_config`（**命令层显式调用**；
  2026-09-21 事件总线重构后不再有 `ConfigReloaded` 订阅者，见 `doc/Architecture.md`
  的「事实通知与核心动作分离」）

**结果**：设置页改开关/间隔即时生效，无需重启客户端。

**问题**：写入路径每次按 `language` 重新派生文件名，加载则靠「语言派生名优先 + 后缀探测」猜；

## 五、复审追加修复（2026-09-21）

PR 复审提出两条，逐条核实后**均成立**，已修复并各自补了锁定用例。

### 复审 1（MEDIUM，9/10）—— `ConfigReloaded` 在生产链路从未发布

**核实**：成立，且比我原先的判断更严重。

- `ConfigService::update`（`update_config` 命令、主题切换、`switch_oj` 的持久化都走它）
  **只落盘不发事件**；
- 唯一发布者 `ConfigService::reload` 只由 `reload_config` 命令触发，而该命令在前端
  **没有任何调用方**（`config.bridge.ts` 的 `reloadConfig` 只被 spec 的 mock 引用）。

**影响**：P48 那条「设置改完立即生效」实际不成立 —— 订阅者永远等不到事件，仍要重开题目
（下一次 `load_workspace`）才生效。

**修复**：`update` 持久化成功后同样发布 `ConfigReloaded`；**持久化失败时不发布**
（磁盘与内存已不一致，让订阅者按「新配置已生效」行动会掩盖问题）。订阅侧改为经
`tauri::async_runtime::spawn` 执行同步 —— auto-save 启停需要 tokio 上下文，不该把
订阅者的正确性建立在「发布方一定在 tokio 上下文里」这个隐含前提上（P39 踩过这个坑）。

**证伪**：临时移除 `update` 里的发布 → 新用例失败于 `left: 0, right: 1`（正是生产断链的形态）。

### 复审 2（LOW，7/10）—— `start_auto_save` 的启停/登记无统一锁

**核实**：成立。原实现是「`stop_auto_save()`（取一次 handle 锁）→ spawn → 再取锁登记」，
三处分三次取锁：并发两个调用各自停掉「当时存在的」任务、各自 spawn，**后登记者的句柄覆盖
先登记者** → 先起的循环成为无人可停的孤儿任务，`stop_auto_save` 之后仍在按自己的节拍写盘
（表现为「关了自动保存却还在保存」）。

**修复**：把「停旧的 → 起新的 → 登记句柄」放进同一把锁的临界区（锁序固定为
`handle → interval`，与 `stop_auto_save` 一致；循环体不取这把锁，无死锁面）。注意
`std::sync::Mutex` 不可重入，尾部的登记必须复用开头的 guard。

**证伪**：新增并发用例（8 线程并发 `start_auto_save` → `stop_auto_save` → 弄脏工作区 →
静候两个节拍 → 断言仍是脏的）。**修复前 4/4 失败，修复后 3/3 通过**。

> 复现过程的两个教训（都属「验证方法本身出错」）：
> 1. 用 `Copy-Item` 还原文件时它**保留源文件的 mtime**，cargo 判定「源比上次构建旧」而跳过重建，
>    跑的是旧二进制 —— 得到「修复后仍失败」的错误结论。还原文件后必须强制刷新 mtime 再跑。
> 2. 用 `cargo test … | Select-Object -First N` 之类的**提前终止管道**会把测试进程打断，
>    于是 `TempDir` 的 `Drop` 来不及执行，留下残留目录 —— 看起来像「清理失效」，其实是被测进程被杀。
