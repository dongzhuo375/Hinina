# rank.spec.ts（E2E：实时榜单）

> 源文件：`e2e/specs/rank.spec.ts`；2026-11 审计 C4 补缺——榜单是全应用最复杂的
> 客户端状态机（全量快照/封榜/翻页回滚），此前只有单测。

## 职责

榜单页四个核心形态的端到端行为：加载与实时刷新、封榜横幅、分页翻页与失败回滚、
打星筛选触发的全量快照跨页聚合。

## 核心类型/函数

四个用例：

1. **加载表格、实时刷新状态与参与人数**：形态断言前先等表格行（业务加载标记，
   防轮询空窗期假绿）；「共 N 队」底栏只在 `pages > 1` 渲染，故用 55 队。
2. **封榜**：`sealRank` 选项使 `sealRankTime` 已过 → 横幅两条文案可见，榜单照常
   展示（封榜不是禁用页面）。
3. **翻页与失败回滚**：105 队 → 3 页；翻到第 3 页后等 3.2 秒（用户操作路径的
   查询 memo TTL 为 3 秒——刚加载过的页命中 memo 直接返回、不发请求，失败注入
   不会被消费）再注入失败并折返第 2 页 → 错误条可见、**页码回退到 3**、旧数据
   保留（「旧页的行 + 新页的页码」是历史缺陷形态，页码同步回退是修复语义）。
4. **打星筛选 → 全量快照**：`fetchAllRows` 从第 1 页循环到末页（fake 分页切片，
   页间 400ms 节流），状态行「客户端筛选 · 已加载 55 行」；第 13 队 `rank=-1`
   经筛选可见；手动刷新入口在状态行。

注意：uid 1 = 当前登录用户，其记录被合并为置顶「我」行——页面上**不存在
`team_01`**，行标记一律从 `team_02` 起。

## 逻辑流程

进场 → 榜单路由 → bootstrap 按 `loadRank(contestId, uid, 1)` 加载 → 10s 级轮询；
翻页走 `setPage`（同查询 3s memo 合并）；失败回滚由 `loadRank` 的 `previousPage`
恢复语义承担；star 筛选切换 `groupFilter` 进入全量模式（快照跨页聚合 + 客户端分页）。
