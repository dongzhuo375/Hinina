# mod

## 职责
`core/event/` 模块入口，声明事件系统的三个子模块：`core_event`（事件载荷）、`core_event_bus`（broadcast 总线封装）、`consumer`（受监督消费者循环）。

旧实现（`app_event` + `event_category` + 手写 `event_bus`）已删除：它同时承担「事实通知」与「必须完成的核心动作」两种语义，导致 Token 轮换、OJ 切换、配置热生效三处出现隐式同步依赖。

## 核心类型/函数
无（仅模块声明）。

## 直接依赖
无外部依赖，仅声明子模块。

## 被依赖
- `core::mod`（通过 `pub mod event` 声明）

## 逻辑流程
无（仅模块声明）。

## 设计约束（改动前必读）
- **事实通知与核心动作分离**：事件只表示「某事已经发生」。必须等待结果的动作（落盘、清缓存、持久化会话、清理用户域数据）由 Service / Command 显式完成。
- **单一事件源**：业务代码只经 `CoreEventBus` 发布；禁止为插件、日志或任何子系统再造第二套总线/订阅表/分发器。
- **允许丢失**：`broadcast` 是有限容量异步通道，消费者必须能在 `Lagged` 后经 Service / IPC 查询重新同步。
