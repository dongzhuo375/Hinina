# 插件系统路线图

> 基线：`main@8379772`，最后更新：2026-10-22。
> 当前是“作者/维护者参与的开发模式”，不是“终端用户可自行安装”的产品模式。

## 2. 已知缺口

### 2.1 管理闭环

- 没有目录 inventory：无法区分“未安装 / 已安装未启用 / 审批不足 / 启动失败 / 运行中”。
- `PluginStatus` 只有 `{id, state, error}`；缺名称、版本、权限、网络、启用意图、上次操作时间。
- 没有原子写入 `plugins.json` 的命令；手改文件不会即时撤销已运行实例。
- `stop` 不改变 `enabled`；缺少“持久禁用”语义。
- 没有配置修订/乐观并发控制；两个页面/编辑器可能互相覆盖。
- 早期启动失败（清单、入口、版本）不一定完整留在状态中。

### 2.2 分发与维护

- 授权只绑定插件 ID，没有绑定已审阅代码内容/发布物摘要；同 ID 替换代码可沿用原批准。
- 没有安装预检、路径逃逸/归档炸弹限制、版本与能力差异展示。
- 没有更新/回滚/失败保留旧版本。
- 没有数据占用、备份、导出、删除管理。
- 删除代码默认保留数据；同 ID 重装的继承规则未定义。

### 2.3 宿主能力

- 无配置 schema 子集；`options` 只能是原始 JSON。
- 无系统凭据库/秘密引用；外部服务密钥没有专用管理路径。
- 无全局资源预算；16MiB 是引擎堆限制，不是进程 RSS 上限。
- 无 handler 级独立超时；只有整次事件 30 秒。
- 所有插件生命周期操作共用一把异步锁；多个慢激活会拉长总启动时间。
- 无 Rust DTO ↔ 桥 ↔ TypeScript 的自动化契约测试/生成。
- 诊断缺少贯穿一次 handler 的关联 ID、耗时和失败阶段。

### 2.4 业务插件

- “第一次 AC”定义未定：当前账号对当前比赛某题的第一次可见 AC？是否含赛前/赛后？如何处理重判/同时间提交？
- 本人查询不能证明“全场所有队伍的第一次 AC”。
- 跨页无事务快照；需按 `submissionId` 去重，必要时重扫。
- 需要显式可恢复状态、租期/重试预算、外部幂等键；本地 CAS 不能保证远端 exactly-once。
- 事件 `submission.judged` 没有 OJ/用户/比赛作用域，只能触发刷新；不能凭 ID 直接派发。

### 2.5 环境验收

- 未在真实 HOJ/Hydro 账号与比赛上联调。
- 未接真实外部气球/通知服务；HTTP 成功路径主要在 transport 层验证。
- 未做受控 DNS 重绑定演练。
- 未做桌面端人工视觉/键盘/读屏验收。
- Linux/macOS 构建与运行未验证。
- 无 CI 流水线。

## 3. 优先级

| 优先级 | 适用范围 | 工作 | 解决什么 |
|---|---|---|---|
| P0 | 作者联调期间 | 真实宿主 → 测试 OJ/外部服务；分页变化/切换/重启/超时 | 证明能力支持目标工作流 |
| P0 | 管理页上线前 | 持久启用/禁用、原子授权/配置写入、撤权时停止并重新装配 | 用户操作能保存、能撤销 |
| P0 | 管理页上线前 | 目录盘点、配置损坏/无效项诊断、早期失败记录 | 区分未安装/未启用/审批不足/启动失败 |
| P0 | 管理页上线前 | 登录前/非比赛时可访问管理入口 | OJ 登录失败时仍能停插件 |
| P0 | 提供更新/导入前 | 发布物摘要、更新差异、失败保留旧版本 | 换代码不会被当成同一份已审阅内容 |
| P1 | 小范围日常使用 | 最小配置表单、诊断列表、数据占用/备份、Resync pending 标记 | 降低手改文件和排障成本 |
| P1 | 有密钥需求时 | 系统凭据库及秘密引用 | 外部服务凭据有独立管理路径 |
| P1 | 多个插件时 | 全局预算、启动耗时测量、按需改进串行等待 | 防止单插件限制叠加拖慢客户端 |
| P2 | 实际需要时 | 标准包导入/回滚、更多平台、限额内存日志 | 提升分发和维护体验 |
| P2 | 不受信任分发前 | 独立进程、来源验证/签名、漏洞响应 | 为更宽信任边界制定独立方案 |
| 暂缓 | — | 插件市场、远程代码热更、依赖求解、自定义 UI、WASM、通用工作流引擎 | 当前需求不足 |

## 4. 管理页设计要点

### 4.1 入口

- 推荐“设置 → 插件”，同时在登录/赛前入口提供“插件管理”，共用同一页面或抽屉。
- 现有设置路由在比赛工作台内，继承登录/比赛守卫；只放在设置里会导致 OJ 登录失败时无法停用插件。
- 第一版面向本机维护者/插件作者；不假装已有管理员角色。OJ 账号、隐藏按钮、前端路由守卫都不是管理授权。

### 4.2 信息结构

```text
插件管理
  全局配置异常/维护状态                         [刷新]
  搜索                状态筛选                  [开发者入口]

  名称 / 版本          自动启用   本次状态          操作
  比赛辅助 1.0.0       已启用     运行中            详情  更多
  通用工具 0.2.0       未启用     已停止            详情  更多
  开发插件 0.1.0       已启用     启动失败          查看原因

  详情
    概览：版本、来源、运行结果、上次操作、需处理的问题
    权限与网络：声明 / 批准 / 当前生效，origin 及内网范围
    配置：插件选项、Resync 间隔、保存后生效方式
    诊断：最近错误、安全操作记录、导出脱敏诊断
    数据与开发：占用、备份、移除；开发目录/构建信息
```

### 4.3 列表原则

- 名称优先，ID 放详情或辅助文本。
- “自动启用意图”与“本次运行结果”分开表达。
- 配置/审批状态（未批准、待应用、版本不兼容、清单无效）不能伪装成 JS 运行状态。
- 没有数据时显示“暂无”，不捏造“健康”。
- 操作：启用/禁用、详情、停止/重启；低频维护放更多菜单。
- 初期没有 OJ 会话/比赛时，插件仍可能 running；显示“查询条件未就绪”，不把 running 解读为“已派发”。

### 4.4 权限与网络

- 同时展示三个集合：Manifest 声明、宿主批准、本次实际生效的交集。
- 存在待应用变更时明确标识。
- 网络显示精确协议/域名/端口；私网 CIDR 与明文 HTTP 分开批准，不能用一个“允许网络”开关替代。
- 查看状态、停止、请求重新同步不需要重复审批；增加能力、扩大网络、导入新代码时展示一次差异审阅。
- 更新不静默扩权；拒绝新能力时允许按原批准交集运行，但说明可能因缺权限失败。

### 4.5 配置

- 第一版：Resync 间隔 + 明确的插件选项编辑 + 错误定位。
- 通用 `options` 可先保留高级 JSON 编辑器。
- 普通用户插件再增加最小 JSON Schema 子集：object、string、boolean、number、enum、required、范围、长度。
- 使用成熟校验器；schema 不联网、不注入脚本。
- 当前 `configSchema` 只接受 `{}`；支持非空 schema 是契约变更，需要版本/兼容策略和测试。
- 配置与授权分开：填写 endpoint 不能顺带批准 origin。
- 秘密字段不能混进普通 JSON。

### 4.6 操作语义

| 操作 | 持久配置 | 本次运行 | 私有数据 | 用户应看到 |
|---|---|---|---|---|
| 启用 | `enabled=true` | 校验并启动 | 保留 | “已启用，运行中”或“已启用，启动失败” |
| 禁用 | `enabled=false` | 撤权、停止；以后不自动启动 | 保留 | 生效结果；停止异常单独提示 |
| 停止 | 不改自动启用意图 | 撤权、停本次 worker | 保留 | “已停止，下次启动应用仍自动启用” |
| 启动 | 使用现有批准；默认要求已启用 | 启动一个实例 | 保留 | 校验/启动结果 |
| 重载 | 应用当前代码、配置、批准 | 先停旧实例、确认退出、再启动 | 保留 | 失败阶段；不能并存 |
| 请求重新同步 | 不变 | 合并一个提示，交由 handler 重查 | 由插件决定 | “已请求”，不承诺即时完成 |
| 修改权限/网络 | 原子写入新批准 | 撤权优先；重新装配交集 | 保留 | 新批准与当前生效是否一致 |
| 更新代码 | 绑定待安装版本和审阅差异 | 安全切换、失败保留可恢复版本 | 默认保留 | 版本、能力变化、应用结果 |
| 移除插件 | 删除启用/批准记录 | 先撤权停用，再移除受管代码 | 默认保留 | 是否保留数据；同 ID 重装规则 |
| 删除私有数据 | 不扩大批准 | 先停止，成功后由用户决定是否再启动 | 显式删除 | 不可逆影响，尤其是去重记录 |

应用一致性：

1. 禁用/撤权优先终止当前能力，然后可靠保存。
2. 磁盘写失败时保持本次撤销，并提示“本次已停止，下次启动的配置尚未保存”，提供重试。
3. 新增授权必须先验证并成功保存，再签发新实例。
4. 停止超时禁止开启替代实例。
5. UI 只按后端返回的复合结果展示，不自行推断成功。
6. 配置写入需要版本号或等价的乐观并发控制；不要给 Manifest 增加语义重复的 version 字段。

## 5. 后续迭代与验收门槛

| 迭代 | 交付范围 | 主要验收 |
|---|---|---|
| A：宿主联调与管理基础 | 专用测试环境、inventory/诊断、持久启用/禁用、审批写入 | 换账号/OJ/比赛、重启、失败保存、撤权在途调用、配置损坏；不依赖通知保证安全 |
| B：最小管理页 | 登录前入口、列表/详情、启用/禁用、状态/权限/网络、重新同步、基础配置 | 无 OJ 会话可停插件；stop 与 disable 语义正确；操作防重复；键盘/读屏/视觉验收 |
| C：本地分发与数据维护 | 导入预检、版本/能力差异、受管更新、备份和保留数据的移除 | 路径逃逸/归档炸弹/重复 ID/摘要不匹配/更新失败/数据保留；撤权与替换不得扩权 |
| D：按反馈增强 | schema 子集、凭据引用、有限诊断历史、资源测量与预算 | 不泄密、schema 不联网、限流/配额可解释、长期运行与发布平台 CI |

## 6. 未决问题

| 问题 | 说明 | 处理时机 |
|---|---|---|
| `PluginManifest.permissions` 使用 `Vec` | 检查为 O(n)，且语义上应去重；当前校验拒绝重复，但类型仍是 Vec | 下次契约清理时改 `HashSet` 或保持并注明 |
| handler 级超时未实现 | 只有整次事件 30 秒；单 handler 无独立预算 | 有实际需求时定义 |
| 授权未绑定代码摘要 | 同 ID 替换代码可沿用原批准 | 安装/更新流程 |
| 游离 Promise 不检测 | 文档强制 await；运行时不 drain、不拒绝检测 | 保持现状；若需求变化再评估 |
| `owner_id` 不序列化 | 经 JSON 缓存往返的记录会丢失归属证据，插件查询只能消费 Provider 直接返回的记录 | 保持现状；不要用缓存记录做归属判断 |
| Linux/macOS 未验证 | 插件运行时构建与测试只在 Windows/MSVC 验证 | 发布平台扩展时补 CI 矩阵 |
| 无真实 OJ/外部服务验收 | 避免制造真实派发 | 专用测试环境联调 |

## 7. 明确暂缓

- 插件市场、远程代码热更新、自动下载执行
- WASM、多引擎调度平台
- 插件自定义页面/UI 扩展
- 依赖求解/包管理器
- 通用工作流引擎
- 自研监控平台、测试专用生产安全后门

## 8. 建议的下一步

1. **文档与代码一致性**：保持本目录、`Architecture.md`、`doc/modules/` 同步。
2. **管理基础契约**：inventory、诊断、原子写入、持久启用意图。
3. **作者联调闭环**：一个与业务无关的测试插件，走真实宿主 → 测试 OJ/外部服务。
4. **业务插件**：在首次 AC 定义、历史完整性、幂等键明确后，由插件作者实现，不放进核心 Service。
